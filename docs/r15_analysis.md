# R15 结果：提示修复与高召回阈值（小规模验证通过，非正式结果）

运行：`scripts/windows/step7_repair.ps1`（4 小时 23 分，含权重恢复）。表格见 `docs/trust_v0_results.md`。val 配对检验：`results/mirror3d_dev_paired_repair_val_v1`。

## 1. 上界：用 GT 掩码时，“先修复提示再交给 PromptDA”明显更好

| C AbsRel | NYU val | NYU 留出 | HAMMER val | HAMMER 留出 |

修复后的 PromptDA 同时拿到了两边的长处：镜面上接近平面填充的水平，物体上比 PromptDA + GT 掩码还好。DOR 也最低（NYU val 0.176，留出 0.161）。

## 2. 用 T v1 掩码时：留出场景大幅改善，val 被一帧拖垮

| C AbsRel | NYU val | NYU 留出 | HAMMER val | HAMMER 留出 |
|---|---:|---:|---:|---:|
| PromptDA-L + T v1（阈值 0.25） | 0.0942 | 0.1617 | 0.0344 | 0.0293 |
| + 高召回阈值 0.67 | 0.0969 | 0.1658 | — | — |
| + 提示修复 | 0.1202 | 0.1335 | 0.0340 | 0.0281 |
| + 高召回阈值 + 提示修复 | 0.1102 | **0.0867** | — | — |

- NYU val 配对差（相对 PromptDA-L + T v1）：高召回 + 修复 +0.016 [−0.028, +0.079]，修复 +0.026 [−0.012, +0.089]，GT 掩码修复 −0.009 [−0.066, +0.064]（16 个场景），都不显著。
- val 的差异几乎全部来自 bathroom_0052/742：从 0.066 变成 0.504，用 GT 掩码修复也是 0.516。这面镜子占图像 28%，贴着上边和左边，可信环带只在两侧，平面外推严重失真。17 帧中有 9 帧修复后更好。
- HAMMER 上修复没有坏处，略有改善。
- 高召回阈值单独使用（不修复）没有收益；只有和修复配合时才有用，因为漏检的像素会污染环带拟合。

## 3. 试过并放弃的保护规则

“环带覆盖不足 3/4 个方向就不做 k2/k3 外推”（阈值事先固定为 0.75，未在 val 上调）：在提示层面修好了 bathroom_0052（0.598 → 0.034），但让其他好几帧变差（如 printer_room_0001 从 0.014 变成 0.554），总体 val 0.089 → 0.094、留出 0.064 → 0.080，不采用。代码保留在 `fill_regions(min_ring_coverage=...)`，默认关闭。

## 4. 结论

- “提示修复 + PromptDA”是目前最有希望的方向：上界在两个数据集上都清楚地好于其他组合。
- 能否稳定地用起来，取决于何时信任平面外推。这又回到选择问题：v1 与逐区域神谕选择之间还差很多。
- 现有样本外镜面帧只有 25 帧，一帧就能翻转结论，无法可靠地设计或验证这类规则。**补充大面积镜面 / 玻璃数据已经是决定性的瓶颈。**
