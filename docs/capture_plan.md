# 自采镜面与玻璃数据：拍摄方案 v1（2026-10-16）

状态：**方案草稿，尚未拍摄。**需要你确认的事项见第 9 节。

## 1. 为什么要自采

现有数据有三个问题，自采数据要一次解决：

1. **真值和方法同源**：Mirror3D 的镜面真值是在镜框边缘用 RANSAC 拟合平面得到的，和我们（以及 Mirror3DNet）的环带拟平面同源，平面类方法的收益会被高估（`docs/related_work_audit.md` §3）。GlassRecon 也一样。
2. **样本量太小**：NYU 的样本外镜面帧只有 25 帧；HAMMER 的 val 和留出各只有 1 个场景，无法做场景级推断（`docs/baselines.md` §4）。
3. **传感器单一**：要验证“提示继承”和 T 是否跨传感器成立，至少需要两种测距原理：主动双目和 ToF。

所以核心要求是：**真值逐像素测得，不用平面拟合；以场景为单位，数量足够做场景 bootstrap；每个场景用多个传感器拍。**

## 2. 真值怎么来：覆盖法

在相机和场景都不动的前提下，拍两种状态：

1. **原始状态**：镜面或玻璃原样，拍 RGB 和原始深度。单帧原始深度作为提示 P，因为部署时模型看到的就是单帧。
2. **覆盖状态**：用不透光的哑光材料把镜面或玻璃表面盖住，再拍深度。多帧取中值后作为真值 GT，测到的是第一表面。

覆盖材料按表面类型选：

| 表面 | 覆盖材料 | 厚度 / 影响 | 备注 |
|---|---|---|---|
| 平面镜、玻璃窗、玻璃门、隔断 | 哑光白色可移除贴纸或牛皮纸（低黏胶带固定） | 约 0.1 mm，可忽略 | 必须不透红外。贴之前在边角试一下，确认传感器读到的是纸面 |
| 曲面镜、小镜子 | 同上，裁成小片拼贴 | 拼缝处标为无效 | |
| 透明物体（杯子、瓶子、透明盒） | 升华型显影喷剂（如 AESUB Blue，约 4 小时自行升华消失） | 约 10 µm，可忽略 | 喷的时候不能碰到物体；喷前先拍完原始状态 |
| 高光金属、亮面瓷砖（次要） | 同上喷剂或贴纸 | | 作为“非镜面高光”对照组 |

**真值质量检查（每个视角都做）：**

- **静止检查**：在未覆盖的背景区域，比较覆盖前后两次深度的中位相对差，必须 < 0.5%，否则说明相机或场景动了，这个视角作废。顺序是原始 → 覆盖 → 再原始，两头的原始状态也要一致。
- **噪声检查**：覆盖状态下连拍 60 帧，记录逐像素标准差。GT 的不确定度要远小于污染阈值 5%，目标是 < 1%。
- **绝对检查**：每块被覆盖的表面，用激光测距仪（精度约 ±1 mm）在 3–5 个点贴近测量，与 GT 对比，记录偏差。这一步只用来验证，不参与生成真值。
- **区域标注**：覆盖物在 RGB 里清晰可见，用覆盖前后的 RGB 差分自动生成材料掩码（镜面 / 玻璃 / 透明物体 / 高光），再人工检查，得到 `material` 字段。

这样得到的 GT 是**同一传感器在哑光表面上的实测值**，不依赖平面假设，曲面镜和透明物体也适用。代价是每个视角要动手覆盖一次。

## 3. 传感器

按优先级排列，**至少需要第 1 和第 2 类各一台**：

| 类别 | 推荐型号 | 原理 | 理由 |
|---|---|---|---|
| 1. 主动双目 | Intel RealSense D435 / D435i / D455 | 结构光辅助的双目 | HAMMER 和 CDM 都有 D435，可以直接对照 |
| 2. ToF | Orbbec Femto Bolt（Azure Kinect DK 的后继）或 Azure Kinect DK | 连续波 ToF | 与双目的失效方式不同：多径反射、玻璃透射 |
| 3. 可选 | Orbbec Gemini 335、ZED 2i | 双目 | 增加型号多样性 |
| 4. 可选 | iPhone Pro LiDAR | dToF（稀疏） | 拿不到原始深度，只作附录 |

- RealSense L515 已停产。手头有的话可以加上，与 HAMMER 对照。
- 多台主动传感器同时开会相互干扰，所以每个视角**依次**只开一台：其他传感器关闭发射器或断电。
- 所有传感器装在同一个刚性支架上，支架固定在三脚架上，用电脑远程触发，拍摄时不碰设备。

## 4. 场景与数量

- **场景的定义**：不同的房间或地点，加上不同的镜面或玻璃物体。同一场景内的不同视角不算独立样本，统计时以场景为单位。
- **目标规模**：48 个场景，其中 24 个以镜面为主（浴室镜、穿衣镜、镜面柜门、曲面镜、带框和无框各半），24 个以玻璃或透明为主（窗、玻璃门、隔断、展柜、透明物体桌面）。
- **每个场景**：4 个视角，覆盖正对、约 30°、约 60°和掠射，距离 0.8–4 m，镜面在画面中所占面积从小到大都有。每个视角 × 每台传感器：
  - 原始状态：30 帧，取第 1 帧作为提示，其余帧用来估计提示的时间噪声；
  - 覆盖状态：60 帧；
  - 再原始状态：10 帧。
- **划分（按场景，拍摄前就定好）**：train 24 / val 8 / test 16 个场景，镜面和玻璃各占一半。
  - test 的 16 个场景拍完后立即计算哈希并封存，方法冻结前不读取。
  - 16 个场景足够做场景 bootstrap，NYU val 也只有 18 个场景。
- **控制变量**：
  - 光照：每个场景至少一个视角在开灯和关灯（或拉上窗帘）各拍一次，用于检验外光对双目的影响；
  - 镜中内容：同一镜面至少一个视角放置远处和近处两种不同的反射内容，用于检验“错误深度来自镜中虚像”。

## 5. 每个视角的拍摄流程（约 10–12 分钟）

1. 架好支架，确认所有传感器的画面都覆盖目标表面。记录场景编号、视角编号、粗略距离和角度。
2. 依次开每台传感器，拍原始状态：RGB、原始深度（不开空洞填充等后处理）、红外图（如能取得）。
3. 覆盖目标表面，期间不碰支架。依次开每台传感器，拍覆盖状态。
4. 拿掉覆盖物，依次拍再原始状态。
5. 用激光测距仪测 3–5 个点并记录。拍一张手机照片记录现场。
6. 当场跑静止检查脚本，第 7 节会提供。不通过就重拍这个视角。

传感器设置（每台都记录到元数据）：

- 分辨率：RealSense 用 848×480 或 1280×720，Femto Bolt 用 NFOV unbinned。
- 关闭所有后处理滤波（spatial、temporal、hole filling）。
- 曝光在视角内固定，深度对齐到 RGB 时使用 SDK 的官方方法。
- 记录 SDK 和固件版本、内参和外参。

## 6. 数据格式与处理

- 每个视角 × 传感器生成一个样本，遵守 `tp/data/schema.py` 的约定：
  - `rgb`：原始状态 RGB；
  - `prompt` / `prompt_valid`：原始状态单帧深度，对齐到 RGB；
  - `gt` / `gt_valid`：覆盖状态 60 帧逐像素中值；标准差 > 1% 或帧有效率 < 80% 的像素设为无效；
  - `material`：材料掩码；
  - `K_rgb` / `K_prompt`；
  - `metadata` 里记录传感器、视角、光照、覆盖材料、三项检查的结果以及原始文件的哈希。
- **为避免与旧协议同源**：`gt_scope` 写成 `measured_first_surface_covered`。镜面区域只有在通过绝对检查后才进入主评测。
- **隐私**：场景中不出现人脸和私人物品。不在家里拍时，事先取得场地方同意。原始数据只存在本地盘，不上传任何云端，与项目约束一致。

## 7. 先做试拍

正式拍摄前，先拍 3 个场景（1 个浴室镜、1 个玻璃门、1 个透明物体桌面），每个 2 个视角，检查四件事：

1. 静止检查的通过率；
2. 覆盖状态下 GT 的噪声，目标 < 1%；
3. 激光测距的绝对偏差；
4. 原始提示里确实有错误值，而不只是空洞：用现有评测算 IR 和污染面积，镜面区域的污染比例应 > 10%。

试拍通过后，我会写 loader（`tp/data/capture.py`）和现场检查脚本，再开始正式拍摄。如果第 4 点不成立，比如某个传感器在镜面上只给空洞，就调整传感器选择。

## 8. 工作量与费用（估计）

- **拍摄**：每个视角约 12 分钟 × 每场景 4 个视角 + 布置 20 分钟 ≈ 每场景 70 分钟。48 个场景约 56 小时，按半天制约 2–3 周。
- **处理**：loader、检查、掩码复核，约 1 周。
- **费用**：
  - 已有传感器时：喷剂约 2–3 罐、贴纸和胶带、激光测距仪，合计约 1000–1500 元；
  - 需要新购时：D455 约 3000 元，Femto Bolt 约 3000–4000 元（以当前售价为准）。
  - 不涉及付费云资源。
