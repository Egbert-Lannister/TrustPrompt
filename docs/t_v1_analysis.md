# T v1 结果分析（小规模验证通过，非正式结果）

运行：`scripts/windows/step6_t_v1.ps1`，用时 24 分钟。另有在本地工作区补跑的 NYU “PromptDA 底图 + 填充”4 个运行。表格见 `docs/trust_v0_results.md`（包含 v0 和 v1）和 `docs/trust_mask_diagnostics.md`。按留出场景替换误差选中的版本是 real_sim_nofeat。

## 1. v1 没有按预期提高召回

- 选中的阈值反而更低（0.10–0.25），被标记的像素更少。镜面召回：NYU val 最好的 v1 版本为 0.785（v0 最好 0.789）；HAMMER 物体召回从 v0 real 的 0.69 降到 0.33–0.45。
- 原因：选择用的代理（误标的像素换成 D_g）要误标付出 D_g 的误差（约 4–10%），这与很多刚超过 τ 的污染像素的误差相当，所以代理认为“标记”收益不大。我在 decisions §13 里预测会偏向多标，这个预测错了，已更正。
- 另外，real 和 sim 两个版本选中的是第 500 步的 checkpoint，训练不足；替换误差这个目标本身也比较嘈杂。

## 2. 但 PromptDA-L + T v1 掩码已经达到 GT 掩码的水平

|---|---:|---:|---:|---:|
| PromptDA-L + Gate 掩码 | 0.0966 | 0.1662 | 0.0512 | 0.0505 |
| PromptDA-L + 检测器掩码（关闭门控） | 0.0996 | 0.2895 | 0.0362 | 0.0365 |

- NYU val 配对差（相对 PromptDA-L + Gate）：全图 −0.010 [−0.019, −0.003]，镜面 −0.002 [−0.006, +0.001]，18 / 16 个场景。
- 在 PromptDA 路径上，T v1 已经和 GT 掩码相当，在两个数据集上都是最好的可部署组合，DOR 也最低。**这条路径上，可信度已经不再是瓶颈。**

## 3. 镜面的瓶颈在补全：PromptDA 补不好镜面

- 即使给 GT 掩码，PromptDA-L 在镜面上也只到 0.096（val）和 0.166（留出）；而 GT 掩码 + 低自由度填充是 0.090 和 0.064。镜面需要的是平面外推，PromptDA 拿到的是用 D_g 填过的提示，学不出平面。
- 尝试“以 PromptDA 输出为底图、在环带上拟合 k0–k3 再按 v1 选”：
  - GT 掩码：留出场景 0.080（好于 PromptDA + GT 掩码的 0.166），val 0.106（差于 0.096）。
  - T v1 掩码：留出 0.148（好于 0.162），val 0.153（差于 0.094）；val 配对差 +0.059 [−0.007, +0.148]。
  - 结论：填充对漏检非常敏感。漏掉的错误像素既被原样保留，又会进入环带、带偏平面拟合。T 目前的召回（镜面 0.75–0.90）不够。

## 4. 下一步建议

1. **提示修复 + PromptDA**：先用低自由度填充把被屏蔽的区域补成平面（而不是补成 D_g），再交给 PromptDA。先用 GT 掩码测上界（一个 GPU 缓存），如果明显好于 0.096 / 0.166，再接 T。
2. **高召回的 T**：阈值改为在留出场景上满足“主范围召回 ≥ 0.95”时误标最少的那个；或在损失里加大污染像素的权重。代价函数不再用 D_g 代理。
3. **镜面数据**：NYU 的样本外镜面帧只有 25 帧，val 与留出场景的结论多次相反。MP3D / ScanNet 镜面子集（需签使用协议）和自采数据是下一步能否下结论的关键。
