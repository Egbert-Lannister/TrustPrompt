# 主线方案：在 OMNI-DC 内部建模“提示有错”（v1，2026-10-18）

状态：**方案已写定，尚未执行。** 本文所有判据都在任何微调结果之前写定。需要租 GPU 的阶段（P1 及以后）要等你同意再开始；P0 只用本机。

代码引用均指 `princeton-vl/OMNI-DC` 的固定版本 a5ecd35（即 `external/baselines/omnidc`）。

## 1. 要解决的条件和已有证据

**条件。** RGB-D 深度补全的输入是传感器深度（本文叫“提示”）。在镜面和透明表面上，读数有系统性错误：

- 镜面读到的是反射虚像的深度；玻璃读到的是后方背景的深度。
- 这类错误在空间上连成一片，几何上自洽，看起来像一块合理的表面。
- 它们既不是缺失，也不是孤立噪声。

**开发集证据**（test 从未读取）：

- **OMNI-DC 在镜面上几乎照抄错误。** OMNI-DC v1.1 在 NYU val 的主范围 C AbsRel：

  | 输入 | C AbsRel |
  |---|---|
  | 原始提示 | 0.750（继承率 IR 0.93） |
  | 外接 T v1 屏蔽后 | 0.137 |
  | GT 屏蔽 [oracle] | 0.113 |

  - HAMMER 10 个场景的交叉拟合结果：0.209 → 0.143（Holm p = 0.0006）。
  - 来源：`docs/baseline_results.md`、`docs/holm_plugin_v1.md`、`docs/holm_plugin_cf_v1.md`。
- **外接屏蔽有代价。** NYU val 干净像素的 AbsRel 从 0.013 升到 0.071（+439%，判定为“明显变差”）。选择上限分析显示，这部分代价原则上可以避免（`docs/selection_ceiling.md`）。
- **单边信息基本可靠。** 被 T 标记的像素里，真实深度不超过读数（误差在 τ 以内）的占 99%；读数“测近了”的只占约 1%（`docs/onesided_validity.md`）。也就是说，被标记的读数虽然不能当等式用，但可以当“真实深度的上界”用。外接屏蔽把这条信息整块扔掉了。

## 2. OMNI-DC 已经具备什么（代码核查）

| 已有机制 | 位置 | 对我们的意义 |
|---|---|---|
| 逐像素“输入置信度”头（sigmoid） | `src/model/backbone.py` 的 `cfi_dec1/cfi_dec0` | 它就是模型内部的 T |
| 置信度乘以 GRU 的 `weights_input`，作为稀疏深度项的逐像素权重进入可微深度积分层（DDI，带权最小二乘，用共轭梯度求解） | `src/model/ognidc.py:254–262`；`src/model/optim_layer/optim_layer.py` 中的 `batched_input_confidence` | 条件可以直接作用在积分层上 |
| 置信度有监督损失 `ConfInput`（BCE） | `src/loss/submodule/confinputloss.py` | 已有训练接口 |
| 训练时向输入注入噪声 | `src/data/__init__.py:34–51` `add_noise` | 噪声模型和真实错误差距很大，见下 |

几点核查结果：

- **训练噪声是逐像素独立的离群点。** 每个像素以概率 U(0, 0.05) 被替换，替换值取 U[p10, p90]。
- **训练模式里没有稠密的 RGB-D 读数。** `train_full.sh` 的模式是 100–2000 个随机点、SIFT 和 Velodyne 三种。
- **`ConfInput` 的标签是单向的。** 标签为 `torch.abs((sparse_depth - gt) > 0.1)`，`abs` 作用在布尔值上，实际只把“读数比真值远 0.1 以上”（中位数归一化后）标为噪声；读数偏近的离群点被当成干净。

**由此提出的假设**（P0-D1 会检验）：机制本身已经有了，缺的是对这类错误的训练。成片且自洽的错误不像独立离群点，置信度头仍给出高置信度，DDI 就把它们积分进结果。

## 3. 方法：一个训练条件 + 两个模块

**C. 结构化提示错误的合成（训练条件）**

- 复用 `tp.sim`，在训练图像上生成错误：
  - 反射：单视角 z-buffer 渲染镜面虚像；
  - 穿透：环形区域拟合背景平面；
  - 金属：乱值或空洞；
  - 再叠加传感器模型（`tp.sim.sensor`），生成结构光或 ToF 风格的稠密读数。
- 区域来源：
  - 语义掩码，例如 Hypersim 的 NYU40 类别里的 mirror（19）和 window（9）；
  - 用 RANSAC 找到的大平面。
- 同时保留 OMNI-DC 原有的稀疏模式和独立噪声，避免遗忘原有能力。
- 标签按我们的定义 |P − GT| / GT > τ（τ = 0.05）分三类：干净、偏远、偏近。

**A. 方向感知的输入置信度**

- 把 `cfi` 头从 1 个通道改成 3 类（干净 / 偏远 / 偏近），用 C 产生的标签做交叉熵监督，替代原来单向的 BCE。
- 进入 DDI 的等式权重为 `p_clean × weights_input`，和原来的用法一致。
- 主模型不再接收外部的 T。“把 T 图作为输入通道”只作为一个消融。

**B. 单边深度积分**

- 对 `p_far` 高的像素，在 DDI 目标里加一个只罚“预测比读数远”的项：λ_h · p_far · max(0, log D − log P)²。
- 求解方式：DDI 是带权最小二乘，单边项用主动集实现：
  1. 先解一次；
  2. 在“预测已经越过读数”的像素上加入以 log P 为目标、权重为 λ_h·p_far 的项；
  3. 热启动 CG 再解，共 2–3 轮。
- 每一轮只改动权重图，目标始终是 P。OMNI-DC 自带的反向传播可以直接沿用，主动集在一轮内视为常数。
- 新增代码集中在权重的组合上。

## 6. 事先写定的判据

**主检验族**：Holm 校正，α = 0.05；指标为主范围 C AbsRel；成对场景 bootstrap，10000 次重采样。

| 假设 | 内容 | 人群 |
|---|---|---|
| H1 | F2（原始提示）优于 R1（内化优于外接） | NYU val |
| H2 | F2 优于 R1 | HAMMER 10 场景 |
| H3 | F2 优于 F0（提升不是来自微调本身） | NYU val |
| H4 | F2 优于 F0 | HAMMER 10 场景 |

- 某个配置没跑出来，就按 p = 1 留在族里。
- **次要分析**（单独成族或只做描述）：F2 对 F1（模块 B 的贡献）、F1 对 F0（合成数据的贡献），以及 NYU train 留出场景上的结果。

**非劣条件**（任何主张都必须满足）：

- **N1，干净区域：** F2 的干净像素 AbsRel 对 R0 不“明显变差”。“明显变差”沿用 §18 的定义：配对差的 95% CI 下界 > 0，且均值上升 > 20%。同时报告 F2 对 R1 在干净区域上的变化（预期改善）。
- **N2，通用补全：** F2 在第 4 节列出的通用评测集上的平均 REL ≤ 1.05 × R0。

**“主张成立”的定义：** H1 和 H2 都被拒绝，并且 N1、N2 都满足。只有 NYU 一边成立时，如实写作“只在镜面上成立”。

## 8. 和 Marigold-DC 引导线的关系

Marigold-DC 引导线（`docs/marigold_guidance_plan.md`）用不训练的方式，先在本机检验模块 B 的前提：同一个检测器下，“把被标记的读数当单边约束”是否比“删掉它”更好。它不替代 B，原因如下：

- B 在 DDI 内部，置信度是学出来的；Marigold-DC 用的是外部 T 和扩散引导。
- 如果 Marigold-DC 在 GT 标记下，单边相对屏蔽的提升也不到 10%（M1 的 ceiling），B 在 P2 降为一个消融，主线以 A + C 为主。

## 9. 风险和应对

- **合成与真实的差距：** 单视角渲染画不出视野外的反射内容，这些像素记为 unresolved；所以 NYU train 的真实镜面错误必须进入训练。D3 会比较合成和真实错误的统计。
- **NYU train 只有 76 张：** 以合成数据为主，用留出场景监控过拟合。
- **OMNI-DC 不是最新的模型：** 它是唯一公开训练代码的提示/补全框架，而且它的积分层显式暴露了稀疏项权重，最适合承载这个条件。外接 T 对 6 个模型的结果（`docs/holm_plugin_v1.md`）可以说明广度。
- **竞争工作：** MetricAnything 带提示的教师模型和 LingBot-Depth 2.0 都声称处理了相关问题，但尚未公开权重。权重一放出，就按同一协议补测（`docs/related_work_audit.md` §5）。

## 12. P0-D1 结果，以及追加的 D1b（2026-10-19）

**D1 结果**（`docs/omnidc_confidence.md`，开发集诊断）：OMNI-DC 自带的输入置信度几乎分不出错误读数。

| 数据集（主范围） | OMNI-DC AUROC | T 的 AUROC | 错误像素 / 正确像素的平均置信度 | 错误像素中置信度 < 0.5 的比例 |
|---|---|---|---|---|
| NYU | 0.52 | 0.91 | 0.935 / 0.928 | 2.3% |
| HAMMER | 0.43（低于随机） | 0.80 | 0.909 / 0.868 | 6.6% |

- 按 §7 事先写定的判读，AUROC < 0.7，**需要模块 A**。
- 这也支持 §2 的假设：机制本身有，但用独立离群点训练出的置信度认不出成片的、几何上自洽的错误。

**代码核查补充：** 读数进入 OMNI-DC 输出的路径不只有积分层。DySPN 精修在 6 次迭代中，每一次都用自己的置信度把全分辨率的提示重新写回结果（`src/model/dyspn_module.py`：`input = (1 - c) * output + c * sp_dep`）。另外，提示本身也是网络的输入通道。所以一共有三条路径：输入特征、积分层、精修。

**D1b（事先写定，未运行）：** `scripts/omnidc_gates.py`。不重训，对被标记的像素分别关闭积分层路径、再加关精修路径，与直接删除像素（三条路径全关）比较。判读规则写在脚本里：

- 用 GT 标记时，S = (raw − ddi_spn) / (raw − mask)，即不碰网络输入、只关前两条路径能消除多少误差。
- S ≥ 0.8：模块 A 只需要在积分层和精修上降权，网络仍然接收原始提示。
- S ≤ 0.5：模块 A 还必须对网络输入做门控。
- 介于两者之间：两种都要做。
- 同时报告干净区域，用来看只关路径能否避免删除像素对正确像素的损伤。

## 14. D1b 结果：错误读数从三条路径都会进入（2026-10-20）

数据见 `docs/omnidc_gates.md`（OMNI-DC v1.1，不重训；开发集诊断）。主范围 C AbsRel：

| 数据集 | 原始 | GT 标记，只关积分层 | 再关精修 | 直接删除像素 | S（GT） | S（T） |
|---|---|---|---|---|---|---|
| NYU（30 张） | 0.858 | 0.751 | 0.371 | 0.106 | 0.65 | 0.61 |
| HAMMER（90 张） | 0.203 | 0.198 | 0.148 | 0.133 | 0.78 | 0.90 |

- **判读（按事先写定的规则）**：用 GT 标记时，两个数据集的 S 都在 0.5 到 0.8 之间，结论是“两种都要做”。也就是说，模块 A 既要在积分层和精修上降权，也要对网络输入做门控。
- **只关积分层几乎没用**（NYU 只消除了 12%）：DySPN 精修会把全分辨率的提示重新写回来。关掉精修路径后，NYU 上再消除 44%。剩下的约 35% 来自网络特征，因为错误读数本身也是输入通道。
- **干净区域**：用 GT 标记时，三种关法都不伤干净像素（NYU 为 0.013 到 0.014）。用 T 标记时，干净区域变差（NYU 0.014 → 0.033 / 0.052 / 0.059），而且只关积分层也会变差。所以干净区域的损伤主要来自 T 的误报，而不是删除像素这种做法本身。

**模块 A 的设计据此修订**（替代 §3 中“只把 cfi 头改成三类”的写法）：

- 用同一个门控 g（由 p_clean 给出），同时作用在三个入口：
  1. 网络输入：提示乘以 g，同时把 g 作为一个额外的输入通道；
  2. 积分层的输入项权重：g × weights_input；
  3. DySPN 精修：把精修自带的置信度乘以 g。
- g 必须在主干网络看到提示之前算出来，否则主干已经被错误读数影响了。因此 g 由一个轻量的检测分支给出：输入为 DAv2 特征（只依赖 RGB，OMNI-DC 本来就会计算）和原始提示，输出为三类概率，与 OMNI-DC 一起端到端训练，监督标签来自 C 的合成数据。
- 这相当于把 T 放进框架内部，与补全网络联合训练。端到端训练还能让网络学会补偿误报，这正是外接 T 做不到、也是干净区域变差的原因。
- 对比和消融随之调整（P2）：
  - g 只作用在积分层和精修上，不门控网络输入；
  - g 换成冻结的外部 T（即“内化检测器，但不联合训练”）；
  - 原有 cfi 头的三类版本（§3 的原设计）。
- 主检验族 H1–H4 不变。

## 15. D3 / D2 的实现（2026-10-20；代码已实现，小规模验证通过；尚未在全部数据和 GPU 上运行）

**Hypersim 读取**（`tp/data/hypersim.py`）：

- 把像素到光线的映射写成一个 3×3 矩阵，求逆后用 RQ 分解得到 K·R。
- 85 个场景中有 52 个用了移轴参数：像平面与相机 z 轴不垂直，K 带有最多 1.8% 的斜切。处理方法是把相机坐标系旋转 R，深度报告为旋转后坐标系中的 Z。这样反投影能精确还原三维点，再投影回去也能回到原像素（测试覆盖了 4 个场景，包括移轴最强的那几个）。
- `tp.sim.mirror_render` 加入了斜切支持；斜切为 0 时，计算与原来逐位相同。

**条件 C 的合成**（`tp/sim/hypersim_condition.py`）：

- 在标注的表面上直接造错，而不是在随机区域上造：
  - 镜面：用该区域拟合的平面，把可见场景按虚像做 z-buffer 渲染；
  - 窗户：读数等于玻璃深度乘以 1.5 到 4 的系数，相当于看穿玻璃。
- 先用结构光或 ToF 传感器模型生成干净读数；超出量程的读数变成空洞。
- **校准中的发现**（24 帧，不计入正式结果）：单视角渲染只能还原镜面像素的 38%，因为镜子里看到的大多是相机背后的东西。因此加了“背墙”模型（`mirror_render.backwall_depth`，用光线追踪测试过）：在相机背后 0.5 到 3 m 处放一面墙，计算它在镜中的虚像深度。以 0.8 的概率填补，其余保持空洞。
- 用这 24 帧和真实 NYU 镜面对比：

  | 指标 | 合成 | NYU 真实 |
  |---|---|---|
  | 错误像素中偏远的比例 | 0.999 | 0.991 |
  | 空洞比例 | 0.69 | 0.52 |
  | 错误像素相对误差的中位数 | 1.28 | 0.90 |
  | 每张图中错误像素占画面的比例（中位数） | 0.021 | 0.050 |

- D3 的检查原来有一条 R3（“渲染不出来的比例 ≤ 0.3”）。单视角的局限是结构性的，加了背墙模型后，这条规则改为：空洞比例与 NYU 相差不超过 0.2。这次修改是在校准之后、正式运行之前做的，记录在此。

**D2 的门控模块**：

- `tp/omnidc/gate.py`：
  - 输入通道和网络结构都与 T 相同，先验换成 OMNI-DC 自己的 DAv2 相对深度，用 Tukey IRLS 对齐到读数；
  - 初始化时“干净”这一类的偏置为 +4，未训练的门控几乎全开，约 0.96。
- `tp/omnidc/gates.py` 的 `soft_gated`：把同一个 g 同时作用到输入、积分层和精修三个入口。
- `tp/omnidc/model.py` 的 `GatedOMNIDC`：组合上面两者。
- **核查发现**：
  1. 公开的训练代码不提供 v1.1 训练所需的 `mono_dep`（DAv2 相对深度），由 `GatedOMNIDC` 自己计算；
  2. 公开的 v1.1 权重里没有 Laplace 输出置信度头，因此微调损失用 train_full.sh 的配置去掉 SeqLaplace 一项。
- **运行**：`scripts/windows/step14_p0.ps1` 依次跑 D3 统计（`scripts/hypersim_synthesis_stats.py`）和 D2 冒烟测试（`scripts/omnidc_train_smoke.py`）。冒烟测试先检查门控全开时与 OMNI-DC 原输出一致，再跑 3 步训练。
